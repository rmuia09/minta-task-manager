## 2. Deploy backend to Render

### First-time setup

1. Go to https://dashboard.render.com/ → **New** → **Blueprint**
2. Connect your GitHub repo. Render detects `render.yaml`.
3. Select the **Free** plan → **Apply/Deploy**
4. When prompted for `DEMO_PASSWORD`, enter a demo-only password (e.g. `password123`).

The `render.yaml` Blueprint configures:

| Setting | Value |
|---------|-------|
| Root Directory | `backend` |
| Runtime | Node |
| Build Command | `npm ci` |
| Start Command | `npm start` |
| Health Check Path | `/health` |
| Plan | Free |
| `NODE_ENV` | `production` |
| `SEED_DEMO_DATA` | `true` |
| `JWT_SECRET` | Auto-generated by Render |
| `DEMO_PASSWORD` | Supplied privately during setup |

### Verify

```bash
export API_BASE_URL="https://minta-task-manager-api.onrender.com/"
curl "${API_BASE_URL}health"
# → {"status":"ok"}
```

Copy your exact service URL from the Render dashboard (it may have a suffix if the name was taken).

### Backend updates (thereafter)

Render auto-deploys on every push to `main` (`autoDeploy: true`). Just commit and push backend changes:

```bash
git add backend/
git commit -m "Update backend"
git push origin main
```

## 3. Set up Firebase App Distribution (one-time)

1. In Firebase Console, create/select a project.
2. **Project settings → General → Your apps → Add app → Android**
3. Package name: `com.example.taskmanager`
4. Register app. You can **skip** downloading `google-services.json` and skip Firebase SDK steps — App Distribution only needs the app registered.
5. **Project settings → General → Your apps → Android app → copy the App ID** (e.g. `1:1234567890:android:abcdef1234`).

### Authenticate Firebase CLI (one-time)

Requires Node.js 20+:

```bash
nvm use 20
npx --yes firebase-tools@latest login
npx --yes firebase-tools@latest projects:list
```

## 4. Build & distribute the Android app

```bash
cd /Users/richardmuia/Documents/mobile-app-demo

export API_BASE_URL="https://minta-task-manager-api.onrender.com/"
export FIREBASE_APP_ID="1:870273804704:android:f09875a05767bd44c9dcc5"
export FIREBASE_TESTERS="rikkmuia@gmail.com"
./scripts/distribute-android.sh
```

The script:
1. Builds the debug APK against the Render URL
2. Uploads it to Firebase App Distribution as a new release
3. Emails invited testers an installation link

> The script rebuilds from scratch (`:app:clean`) and verifies that the
> generated `BuildConfig.API_BASE_URL` matches the URL you passed, so a stale
> APK can never be uploaded to testers.

### CI-friendly variant

In CI, authenticate with a refresh token instead of an interactive login and
skip the tester invitation if the release is distributed separately:

```bash
export FIREBASE_TOKEN="<refresh token from firebase login:ci>"
export FIREBASE_APP_ID="1:870273804704:android:f09875a05767bd44c9dcc5"
export FIREBASE_TESTERS="rikkmuia@gmail.com"
./scripts/distribute-android.sh
```

### Tester installation

Testers open the Firebase invitation email on their Android device, sign in with that Google account, and install the APK from the Firebase App Distribution tester portal.

### App updates

Re-run the same command whenever you want to push a new build:

```bash
./scripts/distribute-android.sh
```

Testers receive a notification about the new release.

## 6. Limitations

- **Render Free**: service sleeps after ~15 min idle; first request takes ~50s to wake.
- **Firebase App Distribution**: debug build for testers only, not a public Play Store release.
- **No Firebase SDK**: not required — the native app calls Render directly; no CORS needed.
